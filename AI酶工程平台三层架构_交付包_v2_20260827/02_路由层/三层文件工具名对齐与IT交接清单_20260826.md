### 结论
- **真值源（平台线上注册表）只有 IT 能提供**：`GET /api/tools` 导出的 name / parameters / is_async。
- **但比对、清单、修正工作我来**，IT 只需给一份导出。

### 当前已能确认的部分（无需等 IT）
通过历史自测日志 `platform_test_arch_20260822/Q3_ERR_classify.txt` 已锁定已知不一致：

| 项目 | 历史测试值 | 线上实际情况 | 当前资产状态 |

| 扩散设计工具名 | `rf_diffusion_design`（带下划线） | 404 Unknown tool | 已统一为 `rfdiffusion_design`（无下划线），执行层禁用列表已用正确名 |
| 异步调用方式 | 用 `/call` | 13+ 工具返回 400 async-only | catalog 已记录 `async` 标志，执行层须分支 `/submit` + 轮询 `/tasks/{id}` |

### IT 仍需确认的（交付前必过门）
IT 导出线上 `/api/tools` JSON，与执行层 workflow 引用的 ~45 个 `tool_id` 逐条比对，至少确认三件事：
1. **名称精确一致**（区分大小写 / 下划线）。
2. **参数 schema** 与当前平台版本一致（历史自测已记录 14 个参数不符，如 `claim` vs `claims`）。
3. **async 标志** 与调用方式匹配（sync → `/call`；async → `/submit` + 轮询）。

### 执行层自查结果（好消息）
对 5 个 workflow 文件做的 `tool_id` 全量扫描显示：**所有被引用的 tool_id 均存在于 58 工具注册表中，无遗留拼写漂移**。也就是说执行层 ↔ 工具栏目前是自洽的，风险只在「执行层 ↔ 线上接口」这一跳。

### 统计
- 已映射：10 项（含 Rosetta 能量评估，FoldX 不接入）
- 已覆盖（功能由现有工具输出满足，无需新增）：1 项（二级结构分析）
- 待接入（全新能力·阻断项）：1 项（MSA/PSSM·高优先级）
- 人工复核（不建平台工具）：1 项（结构可视化）

### 处理建议
1. **已映射项（10 项）**：保留，作为策略层 → 执行层的桥，无需改策略层（`recommended_tools` 本就是能力标签，不是强制调用）。
2. **已覆盖项（二级结构分析）**：不新增独立工具，执行层引用 `predict_properties`(Chou-Fasman) / `alphafold2_folding` / `esm_if1_design`(DSSP) 的输出即可；从"无对应"更正为"已覆盖"。
3. **Rosetta 能量评估（已映射）**：`rosetta_ddg` 已注册，作为唯一独立 ΔΔG 评估来源，无需加装 FoldX。原计划的"双 ΔΔG 交叉验证"改为由 `mutation_scan`（快速初筛）+ `rosetta_ddg`（精确精验）组合替代，避免 FoldX 商业授权成本。
4. **MSA/PSSM（待接入·高优先级·阻断项）**：补专用 MSA/PSSM 工具，或将 `homolog_msa` 正式定为该步调用工具并配合 `sequence_search`/`blast_search`；PROSS/FireProt 等共识/祖先序列策略核心依赖 MSA。在缺 MSA/PSSM 时，`STAB-CONSENSUS-01` 路线标记为 **BLOCKED / 降级**，不承诺完整执行。
5. **结构可视化（人工复核）**：明确定义"人工 ChimeraX 复核"为人工步骤，**不建平台工具**；属解释辅助、非计算关键，研究员本地判读即可。
