## 一、待接入能力（平台要补的工具，按优先级）

### 1. MSA/PSSM —— 高优先级（阻断项）
- **是什么**：多序列比对（MSA）+ 位置特异性打分矩阵（PSSM）。共识序列 / 祖先序列重构（对应 PROSS、FireProt 等方法）的核心输入；没有它，`STAB-CONSENSUS-01` 策略跑不全。
- **现状**：平台现在只有 `homolog_msa`（作为流程输入物）和 `sequence_search` / `blast_search`（同源搜索），**缺一个独立的"MSA 生成 + PSSM 计算/消费"步骤**。
- **要做的工具（二选一或都做）**：
  - 新增 `msa_build`：输入查询序列（+ 同源集或自动搜库），输出比对文件（FASTA / Stockholm）与 PSSM。
  - 或正式把 `homolog_msa` 定为该步"调用工具"，并配套 `sequence_search` / `blast_search` 取同源。
- **建议实现**：MMseqs2 / Clustal / jackhmmer 做比对，PSSM 由比对导出；小规模可同步，大规模走异步（`/submit`）。
- **责任方**：平台后端 / 待定（TBD）。
- **契约影响**：在 MSA/PSSM 接入前，`STAB-CONSENSUS-01` 路线在路由后标记为 **BLOCKED / 降级输出**，不承诺完整执行（见交接清单第五节问题 4）。

### 2. 结构可视化 —— 人工复核（不建工具）
- **是什么**：把 PDB / 突变结果渲染成可看的图像（突变位点、活性中心、二硫键、loop 等），供人工判读。
- **现状**：平台有折叠预测（esmfold / alphafold2 / rosettafold），但**没有"看"的环节**。
- **处理方式**：**不建平台工具**，明确定义"人工 ChimeraX 复核"为**人工步骤**（不占平台算力，研究员本地看）。后续若算力宽裕再评估加 `structure_render`。
- **责任方**：研究员本地 / 不占 IT 排期。

> 说明：当前唯一待平台接入的能力缺口是 **MSA/PSSM（高优先级·阻断项）**；结构可视化改为人工复核，FoldX 按用户决策不接入（免商业授权）。其余能力（含 `rosetta_ddg`、二级结构分析等）平台已具备或在现有工具输出中已覆盖，详见交叉表 CSV。

## 二、IT 要处理的 API（说清楚）

### 任务
从平台导出线上工具注册表，与执行层 workflow 引用的 `tool_id` 逐项核对，回传差异清单。

### 接口清单
| 接口 | 方法 | 用途 |
|---|---|---|
| `/api/tools` | GET | 导出全部工具的 `name` / `parameters` / `is_async`（**真值源**，IT 必须提供导出） |
| `/api/tools/{tool_name}/call` | POST | 同步调用；若返回 `async-only`，改走提交+轮询 |
| `/api/tools/{tool_name}/submit` | POST | 异步提交，返回 `task_id` |
| `/api/tools/tasks/{task_id}` | GET | 轮询任务状态至终态（completed / failed / …） |

### 核对三件事
1. **名称精确一致**：区分大小写 / 下划线。历史坑：`rf_diffusion_design`（带下划线）→ 404，正确是 `rfdiffusion_design`（无下划线）。
2. **参数 schema 一致**：历史自测已记录 14 处不符（如 `claim` vs `claims`），以线上导出为准逐项核对。
3. **async 标志与调用方式匹配**：`sync → /call`；`async → /submit` + 轮询。**特别重要**：线上 `is_async` 字段在 31/58 个工具上与后端真实行为不一致（25 个误标异步、6 个漏标），**执行器不要预信该字段**，必须先用 `/call` 试探、被拒（`async-only`）再回退 `/submit`。

### 回传内容
差异清单（名称错 / 参数错 / async 错），给对接人（men / 平台侧）。

### 已知坑（5 点）
1. `is_async` 不可信，必须实测回退。
2. 名称大小写 / 下划线（`rf_diffusion_design` → `rfdiffusion_design`）。
3. 参数 schema 14 处不符（`claim` vs `claims`）。
4. `source_anchors`（PROSS / FireProt / ASR / FRESCO / LigandMPNN）是**文献方法名**，不是平台工具，勿当 `tool_id` 注册/调用。
5. 工具总数 **58**（非 55），以线上导出为准。

### 范围边界（重要）
- **IT 本次范围**：导出 `/api/tools` + 核对名称/参数/async + 注册 MSA/PSSM 工具。**结构可视化改为人工 ChimeraX 复核（不建工具）；FoldX 按用户决策不接入（免商业授权）。**
- **不在本次范围**：平台"执行器 / 校验器"的代码实现（确定性调用、步骤记录、`scientific_claim_gate` 拦截等），那是平台后端独立工作流。**当前交付包里的 SKILL.md 是路由/输出规范，不是可执行执行器；若只把 SKILL.md 当提示词注入，无法强制保证计划不漂移、工具不越权、步骤完整执行。**

## 三、输入门控修复说明（v2 新增）

- **原问题**：5 条酶工程 workflow 曾把 `bio_specialty_input_gate` 作为首步工具，但该工具仅支持膜蛋白脱靶 / 配体-受体 / 通路膜蛋白 / 抗体人源化，**不支持酶工程**，会导致正常酶任务被判 `unknown_workflow` / `blocked`。
- **v2 处理**：5 条酶 workflow 首步已改为内部 `intake_review`（**非平台工具**），由 LLM 抽取目标与已知输入、列出缺口并等待用户确认，再由后端契约校验最小必填字段；`bio_specialty_input_gate` 在 catalog / taxonomy 中明确标注"仅限非酶类任务"。
- **交互规则**：第一轮信息不全时，系统先输出"已知 / 缺口 / 建议补充项"，**不阻断分析**；只有在要输出最终定量结论、下单突变或关键对象都不明确时，才升级输入要求。详见执行层 `references/input_policy.md`。
