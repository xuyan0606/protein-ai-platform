# 会话意图识别

## 目的

区分“新项目任务”和“围绕当前结果的追问/补充/修订”，避免用户每次发消息都被当成重新开始一个新流程。

## 意图类型

### 1. NEW_TASK

用户在提出新的工程目标或新的分析任务。

典型信号：
- 新的性质目标
- 新的蛋白/序列/项目
- 明确说“帮我做”“重新开始”“另一个任务”

### 2. FOLLOW_UP

用户在追问上一次结果、要求解释、核对、压缩、改写或补充说明。

典型信号：
- “这个什么意思”
- “再说人话”
- “这版和上一版有什么区别”
- “继续”
- “收尾了，那文件呢”

### 3. INPUT_UPDATE

用户在补充之前任务缺失的信息。

典型信号：
- 新增序列、结构、底物、宿主、实验条件、目标指标
- 提供附件或新数据
- 纠正之前的输入

### 4. TARGET_CHANGE

用户在改变主目标或优先级。

典型信号：
- “不是活性了，先看稳定性”
- “把表达放第一”
- “别做这个目标，改成另一个”

### 5. NON_EXECUTION

用户只是问概念、问规则、问解释，不要求立即进入平台任务。

典型信号：
- “你觉得这个想法有问题吗”
- “这个 skill 是单独写还是放一起”
- “为什么这样分”

## 判定顺序

1. 优先看是否明显是对上一轮结果的追问。
2. 再看是否在补充已有任务信息。
3. 再看是否真的提出新任务。
4. 分不清时，先把它视为 `FOLLOW_UP`，不要重开新流程。

## 行为规则

- `FOLLOW_UP`：继续当前任务上下文，不重新做全量路由。
- `INPUT_UPDATE`：更新当前任务输入，再决定是否继续执行。
- `TARGET_CHANGE`：先重路由，再执行。
- `NEW_TASK`：新建任务上下文。
- `NON_EXECUTION`：直接回答，不启动流程。
