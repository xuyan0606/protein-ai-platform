# 输入策略

## 核心原则

平台采用“先盘点、先告知、后分析”的交互方式：第一轮收到任务后，先由 LLM 识别目标、读取用户已提供的序列/结构/附件并列出信息缺口；在用户补充信息或明确“按现有信息继续”之前，不进入性质分析和候选设计。

输入门是一个会话阶段和后端契约校验，不是必须调用的平台工具。不得把 `bio_specialty_input_gate` 当作五条酶工程 workflow 的前置工具。

## 第一轮处理

1. 接收自然语言、段落、附件、序列、结构文件和上下文。
2. 抽取已知项：主目标、可能的次目标、保持约束、序列/结构、宿主、底物、assay、已有数据和编号信息。
3. 生成“输入盘点”而不是直接启动分析：
   - 已收到的信息。
   - 缺失信息。
   - 缺口等级。
   - 每项信息对后续分析的影响。
   - 最建议优先补充的 1-3 项。
4. 等待用户选择：补充信息、按现有信息继续，或修改目标。

## 最低启动条件

- 有序列或结构文件，并且能识别用户希望优化的主目标：可以完成输入盘点并等待用户确认。
- 用户明确“按现有信息继续”后，即使 assay、宿主、底物或完整结构上下文缺失，也可进入相应 workflow；缺失项必须降级证据等级并写入 `input_gaps`。
- 没有序列、结构或可追溯参考对象：先请求对象信息，不调用候选生成或性质分析工具。
- 主优化目标无法判断，或多个目标无法区分主次：先请求用户指定，不自行选择。

## 缺口等级

### ROUTING_BLOCKER

缺失后无法确定主流程或对象：

- 主优化目标不清。
- 多个优化目标没有主次。
- 没有序列、结构或可追溯参考对象。
- 用户要求坐标级结论，但编号体系和链/成熟链不清。

处理：等待用户反馈，不进入后续分析。

### ANALYSIS_LIMITATION

缺失后仍可分析，但会限制机制判断或候选优先级：

- 底物或竞争底物信息。
- 宿主、信号肽、成熟链和构建体边界。
- 催化残基、结构、同源序列或 MSA。
- 已有稳定性、动力学、表达或筛选数据。
- 反应条件和目标 pH/温度。

处理：先告知用户；用户确认继续后，按现有信息分析，并降低结论等级。

### VALIDATION_LIMITATION

缺失后不影响形成计算假设，但不能形成定量或实验结论：

- WT 对照和同条件 assay。
- 重复数、误差和统计方法。
- 完整 pH 曲线、动力学参数或稳定性实测。
- 表达量、可溶性、胞外活性蛋白等分层数据。

处理：标注为“预测候选/待验证”，不得写成已提升或已验证。

## 用户确认后的处理

- 用户补充信息：更新当前任务上下文，重新输出缺口变化；若主目标和对象已明确，进入 workflow。
- 用户说“继续”“先按现有信息分析”：进入 workflow，保留所有未补齐缺口，不再重复要求完整表单。
- 用户修改目标：重新解析主目标并重新路由。
- 用户只追问解释：保持当前任务，不启动新流程。

## 标准输入盘点输出

```yaml
intake_status: WAITING_FOR_USER_INPUT
known_inputs: []
input_gaps:
  - field: assay_context
    level: ANALYSIS_LIMITATION
    impact: 只能给出方向性候选，不能比较实测提升
    recommended: 建议补充 WT 与突变体的同条件测定方法
recommended_next_inputs: []
user_action_required: provide_missing_inputs|continue_with_current|clarify_target
analysis_started: false
```

面向用户的展示至少包含：

1. 已收到什么。
2. 还缺什么。
3. 最建议先补什么。
4. 不补会影响什么。
5. 等待用户决定是否继续。

## 禁止行为

- 第一轮只因字段不全就调用性质分析或候选设计工具。
- 要求用户一次性填写完整 schema。
- 把 `bio_specialty_input_gate` 当作酶工程通用入口。
- 未经用户确认，擅自把缺失信息按经验补齐。
- 把“用户没有提供”写成“该对象不存在”。
