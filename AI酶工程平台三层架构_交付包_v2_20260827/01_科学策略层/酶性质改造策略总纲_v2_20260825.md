# 酶性质改造策略总纲 v1

> 版本定位：AI 酶改造平台的**科学策略层**。
>
> 本文件回答四个问题：
>
> 1. 当前目标应该考虑哪类改造机制？
> 2. 什么输入条件下可以启用该策略？
> 3. 哪些区域、动作或结论应被禁止？
> 4. 如何验证策略是否真的有效？
>
> 本文件不负责决定具体 API 调用顺序，也不替代工具注册表、工作流路由器和执行器。

---

## 1. 分层边界

平台建议拆成四层：

| 层级 | 负责内容 | 不负责内容 |
|---|---|---|
| 科学策略层 | 改造机制、候选区域、优先级、风险、验证设计 | 具体 API 参数和运行调度 |
| 目标路由层 | 根据用户目标选择 stability、pH、activity、expression、specificity 等路线 | 自行发明新的科学机制 |
| 工具执行层 | 调用工具、记录输入输出、处理同步/异步状态 | 把模型分数直接解释成实验结论 |
| 证据与质控层 | 证据等级、来源追溯、编号核对、结论降级和停止 | 绕过缺口生成完整位点方案 |

**重要原则：**策略层可以推荐“分析方向”，但不能因为某个工具存在，就默认必须调用该工具。

---

## 2. 全局策略规则

### 2.1 目标和约束分离

- `optimization_target`：用户明确要求提高、降低、拓宽或改变的性质。
- `preservation_constraint`：用户要求保持不下降的性质，例如“提高热稳定性但不牺牲活性”。
- `monitor_only`：只观察、不主动优化的性质。

单目标任务不得自动扩展成多目标任务。稳定性、pH、活性、表达和特异性之间默认存在冲突，除非用户明确指定，不得自动并列优化。

### 2.2 证据等级

| 等级 | 名称 | 允许输出 | 不允许输出 |
|---|---|---|---|
| E0 | 经验假设 | 机制方向、候选区域、补数建议 | 确定性位点结论 |
| E1 | 序列/家族证据 | 保守位点、共识方向、初筛候选 | 坐标级机制和实测提升 |
| E2 | 结构/计算证据 | 结构邻域、相互作用假设、优先级排序 | 把预测值写成实验值 |
| E3 | 实验或可核查文献证据 | 条件明确的候选依据、可比较效果 | 跨酶、跨底物、跨 assay 直接照搬 |

证据等级必须绑定到每个策略和每个候选，而不是只在报告末尾给一个总评分。

### 2.3 候选区域分级

- `protected_region`：催化残基、金属/辅因子配位位点、关键底物锚定位点、已确认的结构核心。默认禁止直接改造。
- `priority_region`：与目标机制直接相关、且有结构或家族证据支持的区域。
- `exploratory_region`：远端柔性区、表面电荷区、通道边缘等，适合低风险初筛。
- `unknown_region`：编号、结构、成熟链边界或功能归属不清的区域。禁止直接给位点结论。

### 2.4 通用停止条件

满足任一条件时，平台应停止生成“可下单突变”，转为输出缺口报告：

- 目标指标未定义，或指标之间互相替代。
- WT 序列、成熟链边界或编号体系未确认。
- 催化中心、底物或关键结构域无法确认。
- 只有模型分数，没有可解释机制或交叉证据。
- 结构坐标不可追溯，却要求坐标级结论。
- 预测工具处于 proxy、failed、submitted 或 running 状态，尚未产生可核查产物。
- 实验条件无法与 WT 或文献对照比较。

## 3. 策略卡片统一字段

平台将每条策略读取为一个 `strategy_card`。自然语言说明只是展示层，以下字段是最小数据契约。

```yaml
strategy_id: STRATEGY-EXAMPLE-01
property: stability
objective_scope: [thermostability]
priority: P1
evidence_level: E1
mechanism_class: evolutionary_consensus
use_when: []
required_inputs: []
protected_regions: []
candidate_regions: []
mutation_pattern: []
preferred_order: []
constraints: []
forbidden_actions: []
stop_conditions: []
validation_metrics: []
primary_risks: []
recommended_tools: []
source_anchors: []
platform_output: []
```

字段含义：

| 字段 | 作用 |
|---|---|
| `strategy_id` | 稳定的策略唯一编号 |
| `property` | 所属性质主线 |
| `objective_scope` | 适用目标的细分范围 |
| `priority` | P1 首选、P2 常用备选、P3 探索性 |
| `evidence_level` | 当前策略证据等级，不代表具体候选已验证 |
| `mechanism_class` | 机制分类，用于检索和聚类 |
| `use_when` | 启用条件 |
| `required_inputs` | 必须具备的序列、结构、底物、assay 或宿主信息 |
| `protected_regions` | 默认不允许改造的区域 |
| `candidate_regions` | 优先考察的区域 |
| `mutation_pattern` | 允许考虑的替换方向，不直接等同最终突变 |
| `preferred_order` | 该策略在同一目标中的优先次序 |
| `constraints` | 需要同步监控的性质或工艺条件 |
| `forbidden_actions` | 禁止的推理或设计动作 |
| `stop_conditions` | 触发停止的条件 |
| `validation_metrics` | 实验或计算验收指标 |
| `primary_risks` | 主要失败模式 |
| `recommended_tools` | 仅作工具能力标签，不代表强制调用 |
| `source_anchors` | 文献、数据库或内部实验来源 |
| `platform_output` | 平台应输出的结构化结果 |

# 4. 热稳定性策略卡片

## STAB-CONSENSUS-01：共识序列与祖先序列

```yaml
strategy_id: STAB-CONSENSUS-01
property: stability
objective_scope: [thermostability, half_life, residual_activity]
priority: P1
evidence_level: E1
mechanism_class: evolutionary_consensus
use_when:
  - 同源序列数量和质量足够
  - 序列身份、家族边界和成熟链已经确认
  - 目标位点不属于催化或关键底物结合保护区
required_inputs:
  - target_sequence
  - homolog_msa
  - numbering_mapping
candidate_regions:
  - 低保守但在高稳定同源物中富集的位点
  - 表面环区和结构域界面
  - 与目标酶功能约束不冲突的共识位点
mutation_pattern:
  - 引入同源家族中高频且结构合理的残基
  - 优先单点，再按机制互补关系组合
forbidden_actions:
  - 把共识频率直接当作稳定性证明
  - 未核对编号和成熟链就投射突变位点
stop_conditions:
  - MSA 中同源物过少、序列质量差或家族混杂
  - 共识位点落入催化保护区
validation_metrics:
  - Tm
  - 目标温度残余活性
  - 热处理半衰期
  - 原始条件 specific activity
primary_risks:
  - 共识残基可能改变活性或底物谱
  - 进化频率不等于当前宿主和工艺条件下的最优
recommended_tools:
  - MSA/PSSM
  - homology search
  - structure mapping
  - stability scoring
source_anchors:
  - PROSS
  - FireProt
  - ASR 相关文献
platform_output:
  - 共识支持位点
  - 同源覆盖度
  - 证据等级
  - 活性护栏
```

## STAB-ENERGY-01：能量计算与物理稳定性筛选

```yaml
strategy_id: STAB-ENERGY-01
property: stability
objective_scope: [thermostability, structural_stability]
priority: P1
evidence_level: E2
mechanism_class: energy_based_design
use_when:
  - 有可靠实验结构或可核查预测结构
  - 突变位点和链编号已统一
  - 需要对单点候选做结构层复核
required_inputs:
  - protein_structure
  - mutation_list
  - chain_and_numbering
candidate_regions:
  - 局部疏松区
  - 疏水核心边缘
  - 氢键和盐桥网络缺口
  - 结构域界面
mutation_pattern:
  - 疏水堆积优化
  - 氢键网络补强
  - 盐桥方向优化
  - 空腔填补
forbidden_actions:
  - 把 ΔΔG 预测值写成实测稳定性提升
  - 未确认结构质量时直接依赖单一能量模型
  - 只看稳定性评分而不检查活性保护区
stop_conditions:
  - 结构质量、链、配体或突变编号不清
  - 不同模型结论冲突且没有机制解释
validation_metrics:
  - Tm
  - 热半衰期
  - 目标温度残余活性
  - specific activity
primary_risks:
  - 力场误差
  - 局部稳定性提升导致构象动态性下降
  - 组合突变存在上位性
recommended_tools:
  - Rosetta/FoldX 类能量评估
  - 结构可视化
  - 突变后结构复核
source_anchors:
  - FRESCO
  - Rosetta/FoldX 相关研究
platform_output:
  - ΔΔG 仅作为预测字段
  - 结构依据
  - 活性冲突风险
```

## STAB-FLEX-01：柔性环与局部动态调控

```yaml
strategy_id: STAB-FLEX-01
property: stability
objective_scope: [thermostability, half_life]
priority: P2
evidence_level: E2
mechanism_class: flexibility_control
use_when:
  - 结构或 MD 指出局部高柔性区域
  - 区域不直接承担催化几何和底物识别
candidate_regions:
  - 高 RMSF loop
  - 二级结构末端
  - 结构域连接区
mutation_pattern:
  - loop 中适度引入 Pro
  - 通过疏水或氢键相互作用降低局部熵
  - 对柔性区域进行保守替换
constraints:
  - 保持底物进入、产物释放和催化残基几何
forbidden_actions:
  - 仅凭“Pro 含量低”就直接指定 Pro 突变
  - 以固定 RMSF 阈值替代结构解释
stop_conditions:
  - 柔性区域靠近底物通道且影响催化循环
validation_metrics:
  - Tm
  - 半衰期
  - 初始速率
  - 底物转化率
primary_risks:
  - 过度刚化造成活性下降
  - Pro 引入破坏主链构象
recommended_tools:
  - MD/RMSF
  - 二级结构分析
  - 结构邻域筛选
```

## STAB-NETWORK-01：二硫键、盐桥与界面网络

```yaml
strategy_id: STAB-NETWORK-01
property: stability
objective_scope: [thermostability, extracellular_stability]
priority: P2
evidence_level: E2
mechanism_class: covalent_and_electrostatic_network
use_when:
  - 目标蛋白所在表达环境允许形成相应结构
  - 候选位置的几何关系可核查
candidate_regions:
  - 结构域界面
  - 表面柔性环
  - 盐桥网络缺口
mutation_pattern:
  - 合理几何距离内的 Cys 对
  - E-R、D-K 等盐桥补强
  - 界面氢键网络优化
constraints:
  - 兼容宿主氧化还原环境
  - 不阻碍折叠、分泌和底物结合
forbidden_actions:
  - 将 Cys 成对引入后直接假设形成有效二硫键
  - 在还原性胞质环境中默认二硫键有效
  - 只凭电荷数量变化宣称稳定性提升
stop_conditions:
  - 几何关系、结构环境或表达区室不支持
  - Cys 引入导致聚集或错误配对风险不可控
validation_metrics:
  - Tm
  - 半衰期
  - 还原/非还原条件下的迁移或质谱证据
  - 表达和聚集比例
primary_risks:
  - 错误二硫键
  - 聚集
  - 活性位点几何扰动
```

# 5. pH 最适与 pH 稳域策略卡片

> pH 改造必须单独作为一条性质路线。`pH optimum shift`、`target-pH activity`、`pH stability` 和 `acid/base tolerance` 不能混为一个目标。

## PH-PKA-01：催化环境 pKa 调谐

```yaml
strategy_id: PH-PKA-01
property: pH
objective_scope: [pH_optimum, target_pH_activity]
priority: P1
evidence_level: E2
mechanism_class: catalytic_pKa_tuning
use_when:
  - 目标 pH 区间和 pH-活性曲线已明确
  - 催化残基及其局部静电环境已确认
candidate_regions:
  - 催化残基第二壳层
  - 与催化残基形成氢键、盐桥或偶极作用的邻近位点
mutation_pattern:
  - 通过邻近带电残基调节局部电场
  - 优先保守替换和单点验证
constraints:
  - 保持催化几何
  - 保持原最适区或用户指定区间的活性
forbidden_actions:
  - 未有机制证据时直接改催化残基本身
  - 把表面 pI 变化直接当作催化 pKa 改变
stop_conditions:
  - 目标是 pH 稳定性，但只有短时活性数据
  - 催化几何和质子转移路径未确认
validation_metrics:
  - 完整 pH-活性曲线
  - 目标 pH 相对活性
  - pH 暴露后的残余活性
  - kcat、Km 或 kcat/Km
primary_risks:
  - 催化效率下降
  - 最适 pH 移动但目标 pH 活性不升
```

## PH-NEAR-01：催化位点邻近残基改造

```yaml
strategy_id: PH-NEAR-01
property: pH

priority: P1
evidence_level: E2
mechanism_class: second_shell_electrostatics
use_when:
  - 催化残基已确认
  - 有结构或同源证据支持邻近位点与催化环境相关
candidate_regions:
  - 催化残基第二壳层
  - 活性口袋边缘的电荷网络
  - 底物通道入口的质子传递相关位置
mutation_pattern:
  - Asp/Glu/His/Lys/Arg 等带电残基的保守替换
  - 调整氢键供受体和局部盐桥
constraints:
  - 不直接改变底物锚定和催化几何
forbidden_actions:
  - 只按“加正电/加负电”批量推荐位点
  - 用单点 pH 活性结果代替完整 pH 曲线
validation_metrics:
  - pH-活性曲线
  - 目标 pH 活性
  - kcat/Km
  - 热稳定性护栏
primary_risks:
  - pKa 方向与预期相反
  - 底物结合受损
```

```yaml
strategy_id: PH-SURFACE-01

  - 不检查聚集和可溶性就批量改表面电荷
validation_metrics:
  - 完整 pH 稳定曲线
  - 聚集和可溶性
  - 目标条件下残余活性
```

## PH-HOST-01：表达宿主与糖基化干扰排查

```yaml
strategy_id: PH-HOST-01
property: pH
objective_scope: [secreted_enzyme_pH_profile]
priority: P1
evidence_level: E1
mechanism_class: host_process_confounding_control
use_when:
  - 蛋白在毕赤酵母等真核分泌宿主表达
  - 序列含 N-X-S/T 潜在糖基化 sequon
  - pH 表型与表达、成熟度或糖型可能耦合
required_inputs:
  - host
  - signal_peptide
  - mature_chain
  - glycosylation_sites
candidate_regions:
  - 潜在 N-糖基化位点及其邻域
mutation_pattern:
  - N->Q 作为去糖基化对照
  - 糖基化位点保留、消除和信号肽方案分开比较
constraints:
  - 先区分酶本身 pH 机制与宿主糖基化造成的表观变化
forbidden_actions:
  - 把 N-X-S/T 序列基序直接写成“已发生糖基化”
  - 忽略宿主差异，把毕赤酵母结论外推到芽孢杆菌
stop_conditions:
  - 宿主、构建体或成熟链边界不清
validation_metrics:
  - 目标 pH 活性曲线
  - 糖型或分子量变化
  - 分泌量、活性蛋白比例
```

# 6. 比活力与催化效率策略卡片

## ACT-CATALYTIC-01：催化中心及第一壳层精细调谐

```yaml
strategy_id: ACT-CATALYTIC-01
property: activity
objective_scope: [specific_activity, kcat, kcat_over_Km]
priority: P1
evidence_level: E2
mechanism_class: catalytic_microenvironment
use_when:
  - 底物、催化残基和 assay 指标明确
  - 需要优化催化效率而非单纯提高表达量
candidate_regions:
  - 催化残基第二壳层
  - 过渡态稳定相关残基
  - 底物接触和定位残基
mutation_pattern:
  - 保守替换
  - 调整氢键、电荷、偶极和空间互补

forbidden_actions:
  - 用总活性或表达量替代 specific activity
  - 用单一模型高分直接生成多点组合
stop_conditions:
  - 蛋白量未归一化
  - 目标底物和 assay 条件未定义
validation_metrics:
  - specific activity
  - kcat
  - Km
  - kcat/Km
  - 稳定性护栏
```

# 10. 多目标组合规则

### 10.1 默认优先级

1. 用户明确指定的主目标。
2. 与当前失败表型最直接相关的目标。
3. 需要保持不下降的性质作为约束，而非第二优化目标。
4. 未明确指定时，停止并追问，不自动拼接多条路线。

### 10.2 组合顺序

```text
目标确认
  -> 公共身份与编号核验
  -> 主目标策略卡片
  -> 单点候选和保护区审查
  -> 主目标单点实验
  -> 约束性质验收
  -> 明确的第二目标模块
  -> 组合突变与上位性审查
  -> 多指标实验验证
```

### 10.3 常见组合的硬约束

| 主目标 | 约束或次目标 | 必须同时监控 | 禁止做法 |
|---|---|---|---|
| 稳定性 | 活性保持 | Tm/半衰期、specific activity、表达 | 只按 ΔΔG 选组合 |
| 活性 | 稳定性保持 | kcat/Km、Tm/半衰期、表达 | 只按 kcat 预测排序 |
| pH | 原最适区活性保持 | 完整 pH 曲线、目标 pH 活性、稳定性 | 只看单点 pH 活性 |
| 表达 | 活性保持 | 胞外活性蛋白、specific activity、可溶性 | 只看总表达量 |
| 特异性 | 总活性保持 | 目标/竞争底物动力学、ee/E 值、稳定性 | 只测目标底物 |

### 10.4 组合进入条件

组合突变必须同时满足：

- 单点编号已经统一。
- 单点结果有同条件 WT 对照。
- 单点效果方向不冲突。
- 结构距离、机制互补或实验数据支持组合理由。
- 组合后的验收指标和淘汰条件已经提前定义。

平台最终报告必须区分：

- `hypothesis_only`：机制假设，不能下单。

- `literature_supported`：有可核查文献，但需确认跨酶和 assay 可比性。
- `experimentally_supported`：有当前项目的可比实验数据。

# 12. 使用前必须完成的质控

1. 核对文献原文、酶种、序列、突变编号、宿主和 assay 条件。
2. 逐条标记来源是否为真实原始研究、综述、数据库还是平台内部经验。
3. 未核验的精确倍数、温度、pH、文献年份和作者信息不得自动升级为 E3。
4. 工具名只作为能力标签，实际调用必须以当前平台注册表和参数 schema 为准。
5. 任一策略卡片缺少输入前提、停止条件或验证指标时，不得进入自动候选生成。
6. 任何 N-X-S/T 基序只能称为“潜在糖基化位点”，是否实际糖基化必须结合宿主和实验验证。

## 结论

本文件承担“策略层”职责：

- 它定义不同性质的科学改造方向。
- 它给出启用条件、保护区、风险和验证指标。
- 它不决定具体工具调用顺序。
- 它不把模型预测写成实验证据。
- 它不允许平台在输入不足时强行生成位点方案。

下一步接入平台时，应把每个 `strategy_card` 转成 JSON，并由路由器根据 `property`、`objective_scope`、`evidence_state` 和 `host_context` 检索，而不是把整篇 Markdown 一次性注入模型上下文。

# 13. 与路由层、执行层的接线规范

本节把科学策略从“参考知识”转成可被路由层消费的约束。它不替代原有 Word/CSV，也不直接规定 API 参数；它通过稳定的 `strategy_id`、`workflow_id` 和 `step_id` 连接三层资产。

## 13.1 三层数据流

```text
strategy_card
  -> strategy_id / required_inputs / forbidden_actions / validation_metrics
  -> strategy_bindings
  -> workflow_id / step_ids / route gates
  -> tool registry
  -> selected tool / fallback trace / output artifact
  -> validator and scientific_claim_gate
```

## 13.2 接线字段

```yaml
strategy_binding:
  strategy_id: PH-NEAR-01
  property: pH
  workflow_id: WF-PH
  step_ids: [P-03, P-04, P-05, P-06, P-07, P-10, P-11, P-12]
  required_inputs: [catalytic_residues, structure_or_homology, target_pH, pH_curve]
  forbidden_when:
    - only_surface_pI_evidence
    - catalytic_geometry_unconfirmed
  validation_metrics: [pH_activity_curve, target_pH_activity, kcat_over_Km, stability_guardrail]
  candidate_status_before_experiment: hypothesis_only
```

## 13.3 路由层消费规则

1. 先由 Skill 解析用户目标，得到 `primary_property`、`secondary_properties` 和 `preservation_constraints`。
2. 再从本文件和 `strategy_bindings` 检索候选策略卡片。
3. 只有满足 `required_inputs` 的策略卡片才能进入候选路由。
4. 路由器根据 `workflow_id` 选择唯一主流程；不得自行拼接新的流程。
5. 路由器把 `forbidden_actions` 转成 `forbidden_steps` 或执行门控。
6. 路由器把 `validation_metrics` 转成最终验收项。

## 13.4 执行层消费规则

1. 执行器只允许调用绑定表中声明的 `step_id` 和当前工具注册表中的真实 `tool_id`。
2. 工具失败时只能按同一工具组切换替补，并记录 `fallback_level`、`fallback_reason` 和证据降级。
3. 任何未绑定的策略动作标记为 `unplanned_action`，停止后续设计步骤。
4. 只有实验结果或可核查同项目证据，才能把候选状态升级为 `experimentally_supported`。
5. 预测分数、代理结果、计划结果和文献外推均不得升级为实验证据。

## 13.5 pH 的独立口径

- `pH_optimum`、`target_pH_activity`、`pH_window`、`pH_stability` 和 `acid_base_tolerance` 统一归入 `property: pH`、`workflow_id: WF-PH`。
- 普通热稳定性、半衰期、溶剂耐受和蛋白酶耐受归入 `property: stability`、`workflow_id: WF-STABILITY`。
- 不能因为稳定性流程中出现 pH 条件，就把所有 pH 任务路由为稳定性。
- pH 任务中涉及糖基化、宿主加工或分泌的内容，作为受控条件模块，不自动把表达升级为第二优化目标。

## 13.6 最小闭环验收

平台只有同时满足以下条件，才可将策略层视为“已接入”：

- `strategy_id` 能查到唯一 `workflow_id`。
- 每个策略动作都能映射到至少一个 `step_id`。
- 执行记录保存实际 `tool_id` 和输出产物。
- 禁止动作能阻断不允许的步骤。
- 验收指标进入最终报告。
- 路由、策略和执行校验全部通过。
