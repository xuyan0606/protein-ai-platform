# Matvenus 多会话调研总结

## 调研范围

本轮已读取当前登录态下 Matvenus 会话列表中的全部 14 个会话：

- 会话索引：`matvenus-research/index.json`
- 原始事件：`matvenus-research/raw/*.stream-events.json`
- 复盘稿：`matvenus-research/reviews/*.review.md`
- 总报告：`matvenus-research/summary.md`

覆盖主题包括：

- 388 aa 酶比活力与热稳定性提升
- 淀粉酶最适 pH 从 6.0 调至 4.5
- 木聚糖酶比活力提高
- 双底物催化效率优化
- 高钙离子依赖性降低
- 蛋白对接在酶改造中的适用边界
- 湿实验反馈后的组合突变迭代

## 共同工作流

14 个会话里最稳定、最值得迁移的工作流如下：

1. **先做输入预检**
   - 检查用户给的是序列、PDB、底物结构、实验表还是纯问题。
   - 检查工具是否接受该输入格式。
   - 先跑 preflight，再让用户确认是否提交正式任务。

2. **先划禁改区，再谈改造**
   - 用功能残基预测、保守性、催化残基、口袋、金属/辅因子位点划分禁区。
   - 明确哪些位点不能碰，避免实验一开始就产生死变体。

3. **候选位点分层输出**
   - 双收益位点：活性和稳定性都可能提高。
   - 单目标位点：只提高 pH、热稳定性、比活力或底物选择性。
   - 风险位点：可能失活、降稳、表达下降或编号不确定。
   - 组合位点：机制互补、空间分离、实验成本递增。

4. **把工具结果转成实验批次**
   - 输出不是只给 Top 排名，而是给“第一批做什么、第二批怎么补、失败后怎么改”。
   - 常见格式是 Top 6、Top 10、15 个高收益突变 CSV、三批次实验优先级。

5. **湿实验反馈后重构假设**
   - 当实验结果与模型预测不一致时，会重新解释机制，而不是直接否定实验。
   - 典型例子：
     - P338T：预测降稳，但实验显示比活升、稳定性降，于是重构为 activity-stability trade-off。
     - 淀粉酶组合：实测发现同类 pH 位点叠加出现负上位性，后续改为一个 pH 位点 + 一个稳定性位点。

6. **组合突变采用梯度推进**
   - 不把所有高分单点直接拼接。
   - 先做低成本单点/双点验证。
   - 用第一轮实验结果判断是否进入三点或四点组合。

## 特别值得借鉴的点

### 1. 预测与实验冲突处理

Matvenus 做得比较好的地方是：当用户给出湿实验数据后，会把实验数据作为更高优先级证据处理。

本平台应学习：

- 明确列出“原预测 vs 实验结果”。
- 判断差异属于模型盲区、编号错误、底物体系差异、表达/折叠效应，还是真实别构效应。
- 用实验反馈更新下一轮设计目标。

### 2. 上位性分析

淀粉酶会话展示了一个重要模式：

- 两个同类口袋 pH 改造位点叠加，可能出现负上位性。
- 一个 pH 位点 + 一个远离口袋的稳定性位点，通常更容易正交叠加。
- 空间距离、机制类型和单点表型都要同时考虑。

本平台后续组合突变推荐应强制检查：

- 空间距离
- 是否同一机制
- 是否同一口袋/通道
- 是否都改变电荷或都刚化同一 loop
- 单点实验数据是否支持组合

### 3. 实验批次化输出

Matvenus 的输出经常直接面向实验人员：

- “先做前 6 个”
- “先验证单点，再组合 2-3 个”
- “CSV 可直接用于引物设计和实验记录”
- “失败后反馈数据继续第二轮”

这比只输出一份解释报告更有执行价值。

### 4. 动态探索/深耕比例

湿实验反馈会话里提到的 70/30 不是固定规则，而是根据项目阶段和预测命中率调整：

- 预测命中率高：可增加探索位点比例。
- 预测命中率低：应增加已知区域深耕比例。
- 用户急需落地：保守深耕。
- 用户追求突破：增加远端/别构探索。

本平台可以把它做成“下一轮设计策略参数”。

## 不能照搬的点

### 1. 过强的成功率和倍数表达

多个会话里出现“成功率 >90%”“提升 5-20 倍”“几乎 100%”这类强表述。除非有明确数据来源，否则本平台不应照搬。

建议改成：

- 高/中/低置信度
- 计算假设
- 需 DSF/SEC/活性实验证实
- 若有文献或同源实验数据，再给出证据等级

### 2. 编号映射风险

高钙依赖性会话里出现过残基编号线性偏移错误，后续才修正。

本平台必须建立编号门控：

- 用户序列编号
- PDB residue numbering
- UniProt numbering
- 信号肽/前肽/缺失残基
- SIFTS 或 alignment 映射证据

没有编号确认时，不应把文献位点或外部位点直接投射到结构上。

### 3. 文献和统计结论需要强制溯源

有会话里用户追问文献来源后，Matvenus 才补充依据。这说明统计型结论不能默认可信。

本平台应要求：

- 涉及阳性率、倍数提升、家族规律时必须给出处。
- 无出处时只能说“经验假设”。
- 报告中区分计算结果、文献证据、实验反馈。

### 4. 工具参数失败需要更强 schema 防护

淀粉酶 MD 会话中出现多次结构转换参数错误。这对本平台是直接教训：

- 工具调用前必须读 schema。
- preflight 要返回缺失参数、非法参数、可接受输入。
- 失败不能重复同一错误参数。

## 建议接入本平台的功能

### 第一优先级

1. **湿实验反馈入口**
   - 支持录入突变、表达、可溶性、Tm、活性、SEC、底物、pH、温度、备注。
   - 自动生成“预测 vs 实验”对照表。

2. **组合突变上位性检查器**
   - 输入多个单点及其表型。
   - 检查空间距离、机制重叠、功能表面冲突、同口袋电荷冲突。
   - 输出组合风险等级。

3. **残基编号确认门控**
   - 在 PDB/UniProt/用户序列未映射前，阻止自动高亮或推荐结构位点组合。

4. **报告证据等级**
   - 将“计算预测、文献证据、湿实验反馈、结构/MD支持、未知假设”分层展示。

### 第二优先级

1. **实验批次导出**
   - Top 6 / Top 10 / 三批次候选 CSV。
   - 包含突变、机制、优先级、引物备注、检测项目。

2. **动态探索/深耕策略**
   - 根据第一轮命中率决定下一轮保守深耕还是探索远端/别构位点。

3. **结构化会话事件**
   - 本平台后端 SSE 增加 `step / report / tool_call / evidence` 事件。
   - 便于复盘、日报、导出 SOP。

## 已经接入的内容

- Matvenus Markdown 样式已迁移到 `MarkdownView`。
- `stream_events` 提取器已支持真实会话复盘。
- `ENZYME_ENGINEERING_REPORT_PROTOCOL` 已接入后端 agent：
  - 输入预检
  - 候选分层
  - 预测与湿实验冲突重构
  - activity-stability trade-off
  - 梯度实验方案
  - Go/No-Go 决策

## 下一步

建议优先把“湿实验反馈入口 + 组合突变上位性检查器 + 编号门控”接入平台。这三项能直接把 Matvenus 多会话中最有价值的闭环能力变成产品能力，同时规避它暴露出的过度自信、编号错误和证据不清问题。
